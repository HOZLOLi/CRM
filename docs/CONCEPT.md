# فیروزه — سند مفهومی CRM

> نسخه ۰٫۱ · وضعیت: پیش‌نمایش کارکردنی

## ۱. مسئله

تیم‌های فروش کوچک و متوسط ایرانی معمولاً بین اکسل، واتس‌اپ و حافظهٔ افراد پخش شده‌اند.
نتیجه: معامله‌ها گم می‌شوند، پیگیری‌ها فراموش می‌شوند، و مدیر فروش هیچ تصویر لحظه‌ای از قیف ندارد.

**فیروزه** یک فضای کاری واحد است که این سه چیز را کنار هم می‌گذارد: قیف فروش، دفترچهٔ
مخاطبین، و کارهای روزانه — با یک دستیار هوش مصنوعی که همین داده‌ها را می‌شناسد.

## ۲. پرسوناها

| پرسونا | نقش | چه می‌خواهد |
|---|---|---|
| مدیر فروش | `manager` | تصویر لحظه‌ای از قیف، نرخ برد، و کارهای عقب‌افتادهٔ تیم |
| کارشناس فروش | `rep` | بداند امروز با چه کسی تماس بگیرد و چه چیزی را پیگیری کند |
| مدیر سیستم | `admin` | مدیریت کاربران، ماژول‌ها و پیکربندی هوش مصنوعی |

## ۴. معماری

```
┌──────────────────────────────────────────────────────────────┐
│  مرورگر (PWA — ویندوز و موبایل)                              │
│  React 19 · Tailwind v4 · Motion · dnd-kit                   │
└───────────────────────────┬──────────────────────────────────┘
                            │ fetch / RSC
┌───────────────────────────▼──────────────────────────────────┐
│  Next.js 15 (App Router)                                     │
│  ┌────────────────┐  ┌────────────────┐  ┌────────────────┐  │
│  │ Route Handlers │→ │ Service layer  │→ │ Prisma Client  │  │
│  │ (HTTP + Zod)   │  │ (business)     │  │ (data access)  │  │
│  └────────────────┘  └────────────────┘  └───────┬────────┘  │
│  ┌────────────────────────────────────────────┐  │           │
│  │ AI layer (provider-agnostic, OpenAI-compat)│  │           │
│  └────────────────────────────────────────────┘  │           │
└──────────────────────────────────────────────────┼───────────┘
                                                   │
                                    ┌──────────────▼───────────┐
                                    │ SQLite (dev) / Postgres  │
                                    └──────────────────────────┘
```

**لایه‌بندی:** صفحه → Route Handler → سرویس → Prisma. هیچ کوئری‌ای مستقیم در کامپوننت
نوشته نمی‌شود و هیچ اعتبارسنجی‌ای در سرویس تکرار نمی‌شود (Zod در مرز HTTP).

**چرا Next.js فول‌استک؟** یک کدبیس، یک استقرار، و امکان جدا کردن بک‌اند در آینده بدون
بازنویسی فرانت — چون مرز سرویس از روز اول رعایت شده است.

## ۵. مدل داده

```
User ──┬── Company ──┬── Contact ──┬── Deal ──┬── DealItem ── Product
       │             │             │          └── Activity
       │             │             └── Task
       │             └── Activity
       ├── Lead
       ├── Task
       ├── Note
       ├── AuditLog
       └── AiConversation ── AiMessage

Pipeline ── Stage ── Deal
```

نکات کلیدی:

- **پول هرگز `number` نیست.** همهٔ مبالغ `Decimal` (decimal.js) هستند؛ ذخیره در ستون
  `Decimal` پریزما، انتقال به‌صورت رشته در JSON، و محاسبه فقط از طریق `src/lib/money.ts`.
- **چند-مستأجری از روز اول.** هر رکورد `ownerId` دارد؛ افزودن `organizationId` در آینده
  یک مایگریشن است، نه بازنویسی.
- **`AuditLog`** هر تغییر را ثبت می‌کند — ابزار اصلی باگ‌گیری.
- **بدون enum در دیتابیس** تا همان اسکیما روی SQLite و PostgreSQL کار کند.

## ۶. طراحی

**جهت بصری: «فیروزه و زعفران».** فیروزهٔ کاشی و زعفران روی کاغذ سردِ مه‌آلود.
ساختاری، نه تزئینی: خطوط مویی به‌جای سایه، اعداد جدولی برای هر رقم، و یک لهجهٔ رنگی
که کم خرج می‌شود.

| نقش | مقدار |
|---|---|
| کاغذ | `#f2f5f3` |
| سطح | `#ffffff` |
| مرکب | `#0f1a18` |
| فیروزه (اصلی) | `#0b6e6b` |
| زعفران (لهجه) | `#b96f10` |
| رس (خطر) | `#a63a32` |

**تایپوگرافی:** Estedad برای تیترها (هندسی، متمایز)، Vazirmatn برای متن و رابط.
هر دو variable و محلی (`public/fonts`) — بدون وابستگی به CDN.

**حرکت:** یک ورودِ هماهنگ برای پوستهٔ اپ، نه fade-up روی هر کارت.
توکن‌ها: `--ease-out-expo`، `--ease-out-quart`، مدت ۱۲۰/۱۸۰/۲۴۰/۳۲۰ms.
`prefers-reduced-motion` رعایت می‌شود.

**واکنش‌گرایی:** Mobile-first. نقاط شکست ۳۶۰ / ۷۶۸ / ۱۰۲۴ / ۱۴۴۰.
موبایل: نوار پایین + کشوی منو، جدول‌ها به کارت تبدیل می‌شوند.
دسکتاپ: ریل کناری جمع‌شو + جدول کامل.

## ۷. هوش مصنوعی

لایهٔ انتزاعی در `src/server/ai/provider.ts`. هر نقطهٔ پایانی سازگار با OpenAI کار می‌کند:

| ارائه‌دهنده | `AI_BASE_URL` |
|---|---|
| OpenRouter | `https://openrouter.ai/api/v1` |
| OpenAI | `https://api.openai.com/v1` |
| Ollama (محلی) | `http://localhost:11434/v1` |
| LM Studio (محلی) | `http://localhost:1234/v1` |

دستیار یک **عکس فوری ساختاریافته** از CRM (قیف، معاملات، وظایف، مخاطبین، سرنخ‌ها) به
مدل می‌دهد و صریحاً از او می‌خواهد فقط بر پایهٔ همان داده پاسخ دهد.

قابلیت‌های بعدی: امتیازدهی خودکار سرنخ، جست‌وجوی معنایی، پیش‌نویس ایمیل، خلاصهٔ جلسه.
