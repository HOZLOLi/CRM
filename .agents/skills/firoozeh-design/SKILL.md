# فیروزه — زبان بصری

این فایل مرجع مطلق ظاهر برنامه است. هر صفحه یا کامپوننت جدید باید بدون استثنا
با این قواعد ساخته شود. اگر جایی این سند با سلیقهٔ لحظه‌ای تعارض داشت، **این سند
برنده است**.

## جهت (Direction)

**«فیروزه و زعفران»** — فیروزهٔ کاشی و زعفران روی کاغذ سردِ مه‌آلود.

ساختاری، نه تزئینی. اطلاعات با **خط مویی، فاصله و عدد** سازمان می‌یابد، نه با کارت،
سایه و گرادیان. یک لهجهٔ رنگی، کم خرج می‌شود. اگر عنصری تزئینی است و اطلاعاتی
منتقل نمی‌کند، حذف شود.

**ممنوعیت‌های صریح** (اینها نشانهٔ طراحی تولیدشده به‌صورت خودکار هستند و این پروژه
آنها را رد کرده است):

- پس‌زمینهٔ کرم گرم (`#F4F1EA`) با سریف پرکنتراست و لهجهٔ تراکوتا
- پس‌زمینهٔ تقریباً مشکی با یک لهجهٔ سبز اسیدی
- جعبه‌های کارتی یکسان با یک `border-radius` برای همه چیز و سایهٔ `rgba(0,0,0,.1)`
- برچسب‌های ALL-CAPS بالای هر تیتر
- `→` چسبیده به انتهای هر دکمه و لینک
- جداسازی هر بخش با یک کارت؛ در این پروژه بخش‌ها با **خط** جدا می‌شوند

## تایپوگرافی

**یک خانواده: وزیر (Vazirmatn).** تیتر، متن، عدد، دکمه — همه با وزیر.
`--font-sans` و `--font-display` هر دو به `--font-vazirmatn` اشاره می‌کنند.

تفکیک تیتر از متن با **وزن و اندازه** انجام می‌شود، نه با خانوادهٔ دیگر.
وزن تیتر ۶۰۰، متن ۴۰۰، برچسب ۵۰۰.

| نقش | کلاس | تعریف |
|---|---|---|
| تیتر | `font-display` | همان وزیر، وزن ۶۰۰ |
| متن | `font-sans` | وزیر ۴۰۰ |
| عدد و مبلغ | `.tnum` | `font-variant-numeric: tabular-nums` |

فونت **محلی** است: `public/fonts/Vazirmatn-var.woff2`. هرگز از CDN یا Google
Fonts استفاده نکن — سرور مغازه ممکن است اینترنت نداشته باشد.

مقیاس اندازه‌ها (px):

| کاربرد | اندازه | وزن |
|---|---|---|
| تیتر صفحه | ۲۲ موبایل / ۲۶ دسکتاپ | ۶۰۰ |
| تیتر پنل | ۱۵ | ۶۰۰ |
| متن جدول | ۱۳ | ۴۰۰ |
| برچسب فرم | ۱۳ | ۵۰۰ |
| متن کمکی | ۱۱٫۵–۱۲٫۵ | ۴۰۰ |
| عدد KPI | ۱۹ موبایل / ۲۶ دسکتاپ | ۵۰۰ (display) |

**ممنوع:** ALL-CAPS فارسی، ایتالیک برای تأکید در تیتر، تغییر رنگ یک کلمه در تیتر،
فونت مونواسپیس برای متن فارسی (فقط برای کد و آدرس لاتین مجاز است).

طول خط: حداکثر ~۷۰ کاراکتر (`max-w-2xl` روی پاراگراف).

## فاصله، شعاع، سایه

- فاصله‌گذاری روی مضرب ۴: `gap-1.5` `gap-2` `gap-3` `gap-5`
- padding پنل: `px-5 py-4` برای سرستون، `px-5 py-5` برای بدنه
- padding صفحه: `px-4 py-5` موبایل، `px-7 py-6` دسکتاپ (`PageBody`)
- شعاع: `4 / 6 / 10 / 14 / 20` — کارت ۹–۱۰، پنل ۱۴، دیالوگ ۱۴، بج تمام‌گرد
- سایه: **تقریباً هیچ.** فقط `--shadow-pop` روی کارت کانبان هنگام hover و
  `--shadow-sheet` روی دیالوگ. جدول و پنل سایه ندارند؛ خط دارند.

## توکن‌های حرکت

```css
--ease-out-quart: cubic-bezier(0.25, 1, 0.5, 1);
--ease-out-expo:  cubic-bezier(0.16, 1, 0.3, 1);
--dur-1: 120ms;  --dur-2: 180ms;  --dur-3: 240ms;  --dur-4: 320ms;
```

قواعد سخت (بر پایهٔ فلسفهٔ Emil Kowalski):

1. **هرگز `ease-in`** روی رابط کاربری. ورودی‌ها کند حس می‌شوند. همیشه `ease-out`.
2. **هرگز `transition: all`.** فقط خصوصیت‌های مشخص.
3. **یک ورود هماهنگ، نه fade-up روی هر کارت.** ورود پوسته یک‌بار؛ کارت‌ها فقط
   هنگام تغییر واقعی (درگ، افزودن، حذف) حرکت می‌کنند.
4. انیمیشن باید **پاسخ به عمل کاربر** باشد، نه تزئین.
5. `prefers-reduced-motion` در `globals.css` سراسری خاموش می‌شود — چیزی برای
   اضافه‌کردن لازم نیست، فقط آن را نشکن (انیمیشن را با JS اجباری نکن).
6. مدت: تعامل کوچک ۱۲۰–۱۸۰ms، پنل/دیالوگ ۲۴۰ms، تغییر چیدمان ۳۲۰ms.
7. `layout` از Motion فقط جایی که چیدمان واقعاً جابه‌جا می‌شود (کانبان، لیست وظایف).

## قرارداد کامپوننت‌ها

همه در `src/components/ui/`. **قبل از ساخت هر عنصر جدید، بررسی کن اینجا نباشد.**

| کامپوننت | فایل | نکته |
|---|---|---|
| `Button` | `button.tsx` | `variant`: primary / secondary / ghost / danger / accent · `size`: sm / md / lg / icon · `whitespace-nowrap` دارد |
| `Input` `Textarea` `Select` `Field` | `input.tsx` | ارتفاع ۴۴px موبایل / ۴۰ دسکتاپ؛ فونت ۱۶px موبایل (**الزامی** تا iOS زوم نکند) |
| `Badge` | `badge.tsx` | `tone`: neutral / turquoise / saffron / clay / moss |
| `Panel` `PanelHeader` `EmptyState` | `panel.tsx` | پنل = `bg-surface + border + radius-lg`، بدون سایه |
| `AiInsight` | `features/ai-insight.tsx` | دکمهٔ «تحلیل با هوش مصنوعی» + پنل پاسخ استریمی — در **هر** ماژول استفاده شود |
| `Stat` `StatGrid` | `stat.tsx` | `StatGrid` با `gap-px` و `bg-line` خطوط جداکننده می‌سازد؛ هر `Stat` باید `bg-surface` داشته باشد |
| `Avatar` | `avatar.tsx` | رنگ از `oklch(...)` با `hue` کاربر — هیچ رنگ ثابتی |
| `Skeleton` | `skeleton.tsx` | — |
| `PageHeader` `PageBody` | `layout/page-header.tsx` | سربرگ همهٔ صفحات ماژول |
| `ResourceTable` | `features/resource-table.tsx` | جدول + کارت موبایل + جست‌وجو + دیالوگ ساخت |

### ساختار اجباری هر صفحهٔ ماژول

```tsx
<>
  <PageHeader title="…" description="…" actions={…} />
  <PageBody className="flex flex-col gap-5">…</PageBody>
</>
```

### جدول در برابر کارت

- دسکتاپ (`md+`): `<table>` با سرستون `bg-surface-2/60` و ردیف `divide-y divide-line`
- موبایل: همان داده به‌صورت `<ul>` از کارت‌های ساده (بدون سایه، با `divide-y`)
- هرگز جدول را روی موبایل با اسکرول افقی رها نکن (به‌جز کانبان که استثناست)

### حالت‌های خالی

همیشه `EmptyState` با یک آیکون خطی، یک جملهٔ روشن، و اگر ممکن است یک اقدام.
متن خالی **دعوت به عمل** است، نه عذرخواهی.

## هوش مصنوعی در هر ماژول (اجباری)

هر صفحهٔ ماژول باید یک نقطهٔ ورود هوش مصنوعی داشته باشد. الگوی واحد:

```tsx
<AiInsight scope="customers" entityId={id} title="تحلیل این مشتری" />
```

- `scope` یکی از: `customers` `orders` `temperature` `cartable` `dashboard` `settings` `products`
- دکمه در `PageHeader` (سمت اقدام‌ها) یا بالای پنل مربوطه
- پاسخ **استریمی** در یک پنل `bg-surface` با همان تایپوگرافی — نه مدال، نه پنجرهٔ شناور
- اگر AI پیکربندی نشده باشد، دکمه غیرفعال با راهنمای `.env`
- هیچ‌گاه داده به بیرون نرود مگر از طریق `AI_BASE_URL` تنظیم‌شده

## RTL

- `<html dir="rtl" lang="fa">` — از روز اول
- از `ms-*` / `me-*` / `start-*` / `end-*` استفاده کن، نه `ml/mr/left/right`
- `dir="ltr"` فقط برای: ایمیل، تلفن، URL، مبلغ با ارز لاتین، `kbd`
- آیکون‌های جهت‌دار (فلش «بعدی») ۱۸۰ درجه بچرخند یا معادل آینه‌ای استفاده شود
- اعداد فارسی با `toPersianDigits` از `src/lib/money.ts`؛ هرگز `toLocaleString` مستقیم

## واکنش‌گرایی

نقاط شکست: `۳۶۰ / ۷۶۸ (md) / ۱۰۲۴ (lg) / ۱۴۴۰`

| ناحیه | موبایل | دسکتاپ |
|---|---|---|
| ناوبری | نوار پایین ۵ آیتم + کشوی ۲۸۰px | ریل کناری ۲۴۸px (جمع‌شو به ۶۸px) |
| صفحه | `px-4` | `px-7` |
| جدول | کارت | جدول |
| کانبان | اسکرول افقی، ستون ۲۶۴px | ۵ ستون هم‌عرض |
| دیالوگ | تمام‌عرض با `inset-x-3` | `max-w-[440px]` وسط |

**الزامات موبایل:**

- ورودی‌ها `text-[16px]` — وگرنه iOS روی فوکوس زوم می‌کند
- هدف لمسی حداقل ۴۴×۴۴px
- نوار پایین `pb-[env(safe-area-inset-bottom)]`
- ارتفاع‌ها با `dvh` نه `vh`

## دسترس‌پذیری (کف کیفیت)

- کنتراست متن ≥ ۴٫۵:۱
- `:focus-visible` سراسری با حلقهٔ فیروزه — حذفش نکن
- هر دکمهٔ آیکونی `aria-label` دارد
- هر ورودی داخل `Field` با `label` واقعی
- `aria-current="page"` روی آیتم فعال ناوبری
- هدف‌های کلیک حداقل ۴۴px روی موبایل
- پیام خطا با `role="alert"`

## صدا و لحن متن

- فارسی محاوره‌ای-حرفه‌ای، دوم‌شخص مفرد («وارد شو»، «ببین»)
- فعل فعال: «ثبت معامله»، نه «ارسال»
- یک عمل، یک نام، در تمام مسیر (دکمه «ثبت» → پیام «ثبت شد»)
- خطا می‌گوید **چه شد** و **چه کار کن** — عذرخواهی نمی‌کند
- عدد همیشه با رقم فارسی و جداکنندهٔ هزارگان

## پیش از تحویل، این چک‌لیست را اجرا کن

1. هیچ رنگ hex خام در کامپوننت نیست
2. هیچ `ease-in` و هیچ `transition: all`
3. صفحه با `PageHeader` + `PageBody` ساخته شده
4. روی ۳۹۰px و ۱۴۴۰px اسکرین‌شات گرفته و بررسی شده
5. حالت خالی، حالت لودینگ و حالت خطا وجود دارد
6. `dir` روی فیلدهای لاتین ست است
7. اعداد با `formatMoney` / `toPersianDigits` نمایش داده می‌شوند
8. `npx tsc --noEmit` و `npx vitest run` پاس می‌شوند
